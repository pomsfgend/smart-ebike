# Как участвовать

## Ветки и задачи
- `main` — стабильная ветка; прямые коммиты только для документации-опечаток.
- Каждая задача из [docs/TASKS.md](docs/TASKS.md) (ID вида `CORE-01`, `BAT-03`) → отдельная ветка `feat/<id>-кратко`, например `feat/bat-03-jbd-uart`.
- `charger-gbt` — отдельный проект быстрой зарядки, в `main` не сливается без согласования.

## Параллельная работа модулей
- Модуль владеет своей папкой: `firmware/lib/<модуль>/`, `docs/<модуль>/`, `hardware/<модуль>.md`.
- **Общие файлы** — `firmware/include/pins.h`, `firmware/include/config.h`, `firmware/lib/core/vehicle_state.h` — меняются отдельным PR с пометкой `[shared]` и ревью владельца ядра.
- Каждое поле `VehicleState` имеет одного писателя (таблица в docs/ARCHITECTURE.md).

## Код
- C++17, Arduino-фреймворк, PlatformIO. Логика без железа выносится в чистые заголовки (пример — `auto_light_logic.h`, `jbd_protocol.h`, `soc_estimator.h`) и покрывается тестами `pio test -e native`.
- Без блокирующих `delay()` в задачах реального времени — только `vTaskDelay/vTaskDelayUntil`.
- Именование: `snake_case` для файлов и пространств имён, `camelCase` для функций, `kConstant` для констант, `CFG_*` для макросов конфигурации.
- Комментарии и документация — на русском.

## Коммиты и PR
- Сообщения: `<модуль>: <что сделано>` (например `rear_light: последовательный поворот`). Ссылка на ID задачи в описании PR.
- Перед PR: `pio run -e esp32s3` и `pio test -e native` проходят; документация модуля обновлена.
- Изменения, влияющие на безопасность (стоп, поворотники, питание, BMS), требуют проверки на стенде и отметки в PR.
