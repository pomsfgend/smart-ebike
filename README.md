# charger-gbt — быстрая зарядка электровелосипеда от станций GB/T DC

Модуль проекта **smart-ebike** (позже станет веткой `charger-gbt`). Задача: заряжать батарею велосипеда
(**LiFePO4 18S, 65,7 В максимум, две параллельные сборки, у каждой своя BMS JBD**) током до **100 А**
от китайских публичных станций постоянного тока с разъёмом **GB/T** (GB/T 20234.3 / 18487.1 / 27930).

Протокол со станцией уже умеет говорить проект-«обманка» пользователя
**[FGMDCharge-FD-ROUND-V2](https://github.com/pomsfgend/FGMDCharge-FD-ROUND-V2)** (ESP32-C3, ESP-IDF 5.0.9).
Этот модуль надстраивается над ним: обманка ведёт сессию со станцией, а наш код подставляет в сообщения
**реальные** данные батареи и управляет силовым преобразователем.

> ⚠️ **Статус: проект/скелет.** Железо не собрано, прошивка на ESP32 не запускалась.
> Чистая логика (кодек GB/T, BMS JBD, супервизор CC/CV) покрыта тестами на ПК (83 проверки, все проходят).

---

## Главное простыми словами

1. **Станция не умеет давать 65 В.** По стандарту GB/T 18487.1-2015 (п. 4.4) станции бывают классов
   **200–500 В, 350–700 В и 500–950 В**. Ниже 200 В станция не опускается (на практике в CML многие
   станции пишут минимум 150–250 В, у пользователя ~240 В — **проверить по логам CML**).
   Поэтому между станцией и батареей **обязательно стоит понижающий преобразователь** (DC-DC) на ~6,6 кВт.
2. **Мы просим у станции примерно 400 В** (в пределах того, что станция объявила в CML) и ток с запасом.
   Станция становится просто «источником энергии». Это сильно упрощает преобразователь: ему нужен
   узкий вход 250–500 В, а не 200–950 В.
3. **Ток в батарею решает ESP по данным двух BMS**, а не станция. Сначала постоянный ток (до 100 А,
   по 50 А на сборку), потом постоянное напряжение 65,7 В с плавным снижением тока до окончания.
4. **Преобразователь — с гальванической развязкой (трансформатором).** Без неё рама велосипеда и вся
   низковольтная часть оказываются под сотнями вольт относительно земли. Это недопустимо.
5. **Выбор схемы преобразователя (решение):** два одинаковых модуля по 3,3 кВт, схема «мост с фазовым
   сдвигом» на готовой микросхеме-контроллере **TI UCC28951**. Быстрая регуляция (сотни кГц) делается
   в железе, ESP32-C3 только задаёт «сколько ампер и сколько вольт» через ЦАП и следит за защитами.
   Отдельного микроконтроллера и отдельной прошивки для силовой части **нет**.
   Подробно и с альтернативами (готовые модули, STM32G474, LLC) — [docs/DCDC_DESIGN.md](docs/DCDC_DESIGN.md).

```
 Станция GB/T ──DC 200..750 В──► [K5/K6 + предзаряд] ─► DC-DC 2×3,3 кВт (изолир.) ─► [предзаряд + K-BAT] ─► 2 × LiFePO4 18S
      │  CAN 250 кбит/с, A+/A- 12 В, CC1/CC2, PE                 ▲ Iref/Vref/EN  │ Vin/Vout/T/FAULT          │ UART (через изоляторы)
      └──────────────────────────► ESP32-C3 (обманка FGMDCharge + компонент fastcharge) ◄─────────────── JBD BMS ×2
```

## ⚡ Безопасность (прочитать до того, как что-то паять)

- **Высокое постоянное напряжение (до 750–1000 В от станции) смертельно.** Постоянный ток не «отпускает»,
  дуга при разрыве под нагрузкой не гаснет сама. Работать только обесточенным, проверять отсутствие
  напряжения прибором категории CAT III 1000 В, одна рука в кармане, рядом второй человек.
- **Изоляция:** ВВ-часть (вход DC-DC) отделена от низковольтной (батарея, рама, ESP) трансформатором
  с усиленной изоляцией. Пути утечки/зазоры — по IEC 62477-1/60664 для 500–1000 В (проверить расчёт).
  Y-конденсаторы между ВВ и PE — минимальные: станция перед зарядом **меряет изоляцию (IMD)**
  и прервёт сессию при утечке.
- **Контакторы:** только DC-рейтинговые (≥ 500 В DC на стороне станции, ≥ 80 В DC / 100 А на стороне
  батареи). Реле «на 250 В AC» не годятся. Нельзя размыкать контакторы под током — сначала ток в 0.
- **Предзаряд** с обеих сторон: конденсаторы DC-DC заряжаются через резистор, затем замыкается основной
  контактор. Иначе — бросок тока в сотни ампер, сварка контактов.
- **Предохранители:** DC-рейтинговые на соответствующее напряжение (на стороне станции ≥ 500 В DC,
  на стороне батареи ≥ 80 В DC). Автомобильные MEGA/ANL рассчитаны на 32–58 В DC — **не подходят**.
- **Контроль изоляции:** станция проверяет изоляцию до заряда. На велосипеде дополнительно — проверка
  изоляции ВВ-части на стенде мегаомметром 1000 В (задача SAFE-2).
- **Аппаратные защиты не зависят от ESP:** перегрузка по току (поцикловая в UCC28951), перенапряжение
  на выходе (компаратор с защёлкой), перегрев. ESP может только *разрешить* работу, но не «отключить» защиту.
- **BMS главнее всех.** Если любая JBD выключила зарядный MOSFET или выставила флаг защиты — заряд стоп.
- **Химия LiFePO4:** не заряжать ниже 0 °C, полный ток только в диапазоне ~15–45 °C (сверить с даташитом ячеек).
- Использование обманки на коммерческих станциях может нарушать правила оператора. Ответственность — на пользователе.

## Структура

```
charger-gbt/
├── README.md                     ← этот файл
├── docs/
│   ├── DCDC_DESIGN.md            ← преобразователь: решение, альтернативы, расчёты, план запуска
│   ├── PROTOCOL.md               ← GB/T 27930: последовательность, сообщения, тайминги, CC1/CC2
│   ├── HARDWARE.md               ← ESP32-C3, CAN, CC2, контакторы, датчики, BMS, питание, пины
│   ├── STATE_MACHINE.md          ← диаграммы состояний (mermaid)
│   ├── INTEGRATION_WITH_SPOOF.md ← что уже есть в FGMDCharge и куда врезать быструю зарядку
│   └── TASKS.md                  ← задачи с критериями приёмки (готовы для GitHub Issues)
└── firmware/                     ← ESP-IDF 5.0.9, ESP32-C3 (как у обманки)
    ├── CMakeLists.txt, sdkconfig.defaults
    ├── main/main.c               ← стендовая прошивка БЕЗ станции (ЛБП вместо станции)
    ├── components/fastcharge/    ← компонент, который кладётся в components/ обманки
    │   ├── include/fc_api.h      ← ИНТЕРФЕЙС с обманкой (хуки)
    │   ├── include/fc_config.h   ← все лимиты: батарея, BMS, DC-DC, «виртуальная» ВВ-батарея
    │   ├── src/gbt_codec.c       ← кодирование/разбор сообщений GB/T 27930 (класс A)
    │   ├── src/gbt_tp_tx.c       ← многопакетная передача RTS/CTS (+ BAM как у обманки)
    │   ├── src/jbd_bms.c         ← протокол JBD BMS (UART)
    │   ├── src/fc_supervisor.c   ← CC/CV, температура, деление тока между сборками, стоп-условия
    │   ├── src/fc_core.c         ← склейка: CAN → станция, супервизор → BCL/BCS/BSM/BCP…
    │   └── src/fc_hw_*.c, fc_task.c ← драйверы ESP-IDF (I2C ЦАП/АЦП/расширитель, UART, задача)
    └── host_tests/               ← тесты на ПК: `./run.sh` или `make test`
```

## Как проверить логику на ПК

```sh
cd firmware/host_tests && ./run.sh      # нужен только gcc
```

Сборка под ESP32-C3 (не проверялась, нужен ESP-IDF 5.0.9, как у обманки):

```sh
cd firmware && idf.py set-target esp32c3 && idf.py build
```

## Что нужно от пользователя (открытые вопросы)

См. конец [docs/TASKS.md](docs/TASKS.md#открытые-вопросы). Коротко: ёмкость сборок (Ач), модель/интерфейс
JBD (UART/RS485/BLE, адрес), соединены ли сборки параллельно постоянно, логи CAN с реальных станций
(особенно CML и поведение при замыкании контакторов), бюджет и готовность паять силовую часть или
купить готовый модуль, какие станции рядом (класс напряжения).
